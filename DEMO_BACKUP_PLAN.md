## 1. Failure Matrix & Emergency Procedures

| Failure Scenario | What Happens? | What Should the Presenter Do? | What Should NOT Be Said? |
| :--- | :--- | :--- | :--- |
| **A. Backend does not start** | Port conflict or process killed. | Run terminal restart: `& .venv\Scripts\uvicorn backend.app.main:app --port 8000`. If port 8000 is occupied, kill existing PID: `Get-Process python \| Stop-Process`. | *"The code has bugs."* / *"We don't know why it's broken."* |
| **B. Frontend does not start** | Vite dev server crashed. | Run `npm --prefix frontend run dev` or open the pre-built production build from `frontend/dist/index.html`. | *"Our UI is broken."* |
| **C. Model takes too long (> 10s)** | First run is cold and CPU is doing background indexing. | Keep talking through the architecture: *"Notice that the model weights are loading locally on this CPU with zero GPU acceleration."* | *"It's frozen."* / *"Let me refresh."* |
| **D. Model throws OOM or fails to load** | Local model weights unavailable or corrupted. | The system automatically engages **`🔒 OFFLINE FALLBACK (Curriculum Engine)`**. Immediately highlight this as a deliberate resilience feature: *"Notice our dual-engine architecture: when RAM is restricted, the deterministic curriculum engine takes over instantly with full textbook citations."* | Never pretend it was AI-generated. Never say *"The AI crashed."* |
| **E. Database has unexpected state** | Demo student has 0 attempts or wrong topic. | Navigate directly to **Personalized Practice** from the sidebar or click **Chemical Reactions and Equations** in the curriculum list. | *"Someone messed up our database."* |
| **F. Internet disappears** | Venue Wi-Fi drops. | Smile and celebrate! *"Notice our topbar indicator: '● On-Device Ready'. Our entire demo runs 100% offline without internet. This proves our core thesis."* | *"Wait, is the Wi-Fi connected?"* |
| **G. AI explanation drawer doesn't open** | Keyboard shortcut / overlay focus issue. | Click the topbar button: **Ask EduNavika AI** or click **"Ask EduNavika AI to explain this"** inside the practice card. | *"The drawer is broken."* |
| **H. Projector / display resolution cutoff** | Projector is 1024x768 or scales weirdly. | Press `Ctrl + -` to zoom out the browser viewport to 90% or 80%. EduNavika's layout is responsive CSS grid. | *"Our CSS isn't working."* |

## 2. Core Golden Rules for Live Presentations
1. **Never Fake Anything:** Never claim deterministic output was generated by the local SLM. The transparent distinction between `⚡ ON-DEVICE AI` and `🔒 OFFLINE FALLBACK` demonstrates architectural maturity that judges respect.
2. **Deterministic Fallback is a Feature:** The offline rule-based fallback guarantees that a student is never left with a blank error screen. Present it with confidence.
3. **Stay Calm & Talk Through the Causal Chain:** If an operation takes 3 seconds, explain the causal chain: *Attempt $\rightarrow$ Learning Event $\rightarrow$ Knowledge Model $\rightarrow$ Adaptive Recommendation*.
